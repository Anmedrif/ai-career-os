# Factual Grounding Checklist

## Purpose

Use this checklist to verify that claims are traceable, appropriately qualified, and consistent with source authority. It is especially important for CVs, professional profiles, job assessments, interview answers, LinkedIn content, and portfolio claims.

## 1. Establish Source Authority

- [ ] Identify the highest-authority source for each fact group.
- [ ] Confirm that the source is current for the intended use.
- [ ] Record the source's scope: facts, evidence, decisions, recommendations, status, or operations.
- [ ] Keep direct evidence separate from user confirmation.
- [ ] Keep source repetition separate from independent corroboration.
- [ ] Do not treat filenames such as `final`, `approved`, or `latest` as authority without an explicit status record.

## 2. Build a Claim Ledger

For each material claim, record:

| Claim ID | Exact claim | Claim type | Source | Source status | Qualification | Decision |
|---|---|---|---|---|---|---|
| C-001 |  | Fact / derived / recommendation |  | Verified / user-confirmed / unresolved |  | Keep / revise / omit / escalate |

Material claims include:

- Identity and public display name
- Employment organization, role, location, and dates
- Duties and responsibility level
- Achievements and metrics
- Education and credentials
- Languages and proficiency levels
- Technical and professional skills
- Tools used
- Project ownership and contribution
- Eligibility, availability, compensation, or relocation
- Approval, action, completion, and outcome status

## 3. Test Each Claim

- [ ] The claim is present in the cited source.
- [ ] Wording does not broaden the source.
- [ ] Dates and ranges preserve supported precision.
- [ ] Functional titles are not represented as legal or contractual titles.
- [ ] A contribution is not rewritten as sole ownership or sole implementation.
- [ ] “In progress” is not rewritten as completed.
- [ ] A self-assessed skill is not called certified or professionally validated.
- [ ] An internal training course is not presented as an independent certification.
- [ ] Approximate or recalled metrics are not described as audited or guaranteed.
- [ ] Project experience is not represented as paid employment.
- [ ] A goal is not represented as a present title or achieved outcome.

## 4. Resolve Source Conflicts

When claims conflict:

1. Record each competing statement exactly enough to distinguish it.
2. Identify source authority, scope, date, and currentness.
3. Check whether a newer explicit user decision resolves the issue.
4. Preserve any remaining limitation.
5. If unresolved and material, omit the claim or use `[USER CONFIRMATION REQUIRED]`.
6. Never average, merge, or choose the most polished version.

## 5. Check Missing Context

- [ ] The evidence covers the full period or scope claimed.
- [ ] Employer/client relationships are not inferred from project names.
- [ ] Metrics have a defined activity, period, and unit.
- [ ] Credential title, issuer, specialization, and completion status are not conflated.
- [ ] Tool use is connected to the correct role or project.
- [ ] Public-use permission is separate from factual confirmation.
- [ ] Confidentiality and privacy restrictions are respected.

## 6. Unsupported-Claim Search

Search explicitly for:

- Senior, expert, advanced, certified, verified, led, owned, built, engineered
- Increased, reduced, improved, achieved, exceeded, top performer
- Exact percentages, volumes, ranks, and time savings
- All, always, every, independently, end-to-end, production-ready
- Current, completed, approved, submitted, published, hired

These words are not automatically wrong. Each use requires evidence appropriate to its meaning.

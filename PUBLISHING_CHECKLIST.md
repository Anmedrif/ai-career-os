# Publishing Checklist

Publication is a consequential external action. Complete every required item for the exact commit proposed for release.

## Content and claims

- [x] The README is accurate, recruiter-readable, and free of inflated claims.
- [x] The reusable professional-profile starter contains placeholders only and no completed real-person profile.
- [x] No unresolved personal-publication marker remains.
- [x] Development attribution and limitations distinguish design, AI assistance, and implementation.
- [x] No file claims a production deployment, foundation-model training, or unsupported AI employment.
- [x] All examples are clearly synthetic.

## Privacy and security

- [x] No phone number, personal email, exact address, identity number, birth date, or immigration detail is present.
- [x] No real application, recruiter, assessment, offer, salary, or correspondence is present.
- [x] No employer-confidential policy, tool, case, document, or screenshot is present.
- [x] No credential, key, token, cookie, password, `.env` file, private URL, or local path is tracked.
- [x] No image or binary file is tracked.
- [x] A contextual privacy review has been completed in addition to pattern scans.

## Repository quality

- [x] The complete tracked tree has been reviewed.
- [x] Markdown files are non-empty and serve a clear purpose.
- [x] Relative links resolve.
- [x] All four Mermaid blocks render correctly.
- [x] Terminology and state labels are consistent.
- [x] The default branch is `main`.
- [x] The proposed release commit is clean and reproducible.

## Governance

- [x] The MIT License applies to the repository.
- [x] No maintainer biography or completed personal profile is included.
- [x] The GitHub repository name, description, public visibility, and topics match the stated project goal.
- [x] The project owner has reviewed the exact release content to be published.
- [x] Publication approval has been given separately from content approval.

## Publication gate

Do not create the public GitHub repository or push any branch until the project owner writes exactly:

`APPROVE PUBLICATION`

That phrase authorizes the publication step only for the reviewed state and approved metadata. Any materially changed state requires a new review.

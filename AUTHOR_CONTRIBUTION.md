# Project Development and Attribution

## Purpose

This document explains how AI Career OS was developed and how contributors or adopters should describe their work accurately. It contains no maintainer biography or private professional information.

## Development Model

AI Career OS is a human-directed, AI-assisted reference project.

Human direction covers:

- defining the problem, goals, and operating principles;
- deciding the architecture and responsibility boundaries;
- setting privacy, source-governance, and approval rules;
- reviewing generated material;
- identifying unsupported claims, contradictions, and missing context;
- accepting, revising, or rejecting proposed changes; and
- authorizing any publication or external action.

AI assistance may cover:

- drafting and restructuring documentation;
- comparing alternatives;
- checking consistency and links;
- suggesting prompts, workflows, templates, and tests; and
- supporting implementation and quality review.

Git history records the public repository's actual changes. It should be used alongside this disclosure when evaluating contributions.

## Credible Project Description

A contributor who materially directed and reviewed this repository may accurately describe the work as:

- designed and documented a privacy-aware multi-agent career-management system;
- defined source-governance, human-approval, and agent-handoff rules;
- created reusable workflows, templates, and synthetic evaluation examples;
- developed an LLM-output evaluation and error-review framework; and
- built the project with AI-assisted development tools and retained human review authority.

The description must be adjusted to match the contributor's actual work and the Git history.

## What the Repository Demonstrates

- Multi-agent responsibility and handoff design
- Prompt and instruction design
- Source-of-truth and state governance
- Human-in-the-Loop controls
- LLM-output evaluation and error analysis
- Privacy-aware career workflow design
- Reusable documentation and templates
- Iterative quality review

## What It Does Not Prove

The repository alone does not prove:

- production deployment or production reliability;
- foundation-model training;
- proprietary machine-learning development;
- advanced programming proficiency;
- paid employment in an AI role;
- independent authorship of every generated line; or
- successful career, hiring, or application outcomes.

## Guidance for Adopters

If you reuse this project:

1. Keep the original license and copyright notice.
2. State clearly what you changed.
3. Use `adapted`, `configured`, or `extended` when those verbs are more accurate than `created`.
4. Do not claim another contributor's commits or design decisions as your own.
5. Replace only placeholders with your verified information.
6. Keep private career data outside a public fork.

## Attribution Boundary

Repository ownership, commit history, and contribution records provide public attribution. Personal biography, contact information, employment history, education, languages, and credentials are intentionally outside this repository.
